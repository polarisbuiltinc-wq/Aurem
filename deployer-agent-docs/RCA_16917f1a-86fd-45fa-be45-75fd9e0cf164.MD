# RCA — Deploy run 16917f1a-86fd-45fa-be45-75fd9e0cf164 (launch-pad-237)

## Verdict
**Source-level build failure. NOT a deployment/manifest issue.** The GitHub Connect funnel telemetry bundle introduced a JSX syntax error in a frontend CTA-wiring file. The fix must be applied in the source environment (this file), then re-triggered. I verified the exact fix in the eph sandbox but cannot persist it to your source — you own that edit.

## Failed step
`build_image` → Cloud Build step #8 `frontend-build-push` → `vite build` (esbuild transform) exited non-zero. Backend deps, yarn install, and the sonner add all succeeded; the build died only at the frontend transform.

## Root cause (exact)
`frontend/src/components/GitHubCard.jsx` contains a **duplicated, orphaned JSX tail appended after the component's real closing brace**. The component `export default function GitHubCard()` opens at line 10 and correctly closes at line 160 (`}`). Lines **161–171** are a botched duplicate-paste of the preceding `<ExternalLink>…</section>);}` block, starting mid-expression with a stray `}}>`.

esbuild reported it verbatim:
```
/workspace/frontend/src/components/GitHubCard.jsx:161:0: ERROR: Unexpected "}"
 159|    );
 160|  }
 161|  }}>
     |  ^
 162|                    <ExternalLink size={11} />
 163|                  </a>
```
`grep` confirmed two top-level closing braces before the fix (line 160 = real close, line 171 = spurious). This is almost certainly an editor/merge artifact from wiring the CTA into `GitHubCard` (one of the 4 CTA entry points in this bundle) — the same component built green in the 4 immediately-prior successful runs, so the duplicate was added by this change set.

## The fix (verified in eph sandbox)
Delete the orphaned duplicate block — **lines 161–171 inclusive** — so the file ends cleanly at the component's real closing brace:

```
...
        </div>
      )}
    </section>
  );
}          <-- line 160, this is the correct, final line of the file
```
i.e. remove everything from line 161 (`}}>`) through line 171 (the trailing `}`).

Equivalent in-place command (what I ran and verified in the sandbox):
```
sed -i '161,171d' frontend/src/components/GitHubCard.jsx
```
After the delete: file is 160 lines, the single top-level closing brace is line 160, and the offending `Unexpected "}"` fragment no longer exists. (Note: the eph pod runs the python backend base image with no node runtime, so I could not execute `vite build` end-to-end here; verification is structural — the exact esbuild error location was removed and the remaining 10–160 is the code that built successfully in prior runs.)

## Why I did not re-run resume_pipeline
The fix lives in your source tree, which is what the pipeline re-pulls. My sandbox edit is ephemeral and does not reach it. Redeploying now would rebuild the identical broken file and fail at the same line. Apply the delete above in the source environment, then re-trigger the deploy.

## Note on the rest of the bundle
Everything else (backend router `routers/github_funnel.py`, the `github_oauth.py` hooks, `githubFunnel.js`, the other 3 CTA sites, the build_hash re-ship) is unaffected by this failure — the build never reached them because the frontend transform aborts the whole `frontend-build-push` step. Once GitHubCard.jsx parses, the build should proceed normally.
