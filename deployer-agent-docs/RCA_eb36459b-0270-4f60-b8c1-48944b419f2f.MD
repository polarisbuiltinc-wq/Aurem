## Symptom (verbatim from Cloud Build)
`vite build` succeeded (`✓ built in 35.48s`), then the post-build prerender crashed:
```
file:///workspace/frontend/scripts/seo-prerender.mjs:25
import { COMPETITORS, COMPARE_HUB, LAST_VERIFIED } from "../src/data/competitors.js";
                      ^^^^^^^^^^^
SyntaxError: Named export 'COMPARE_HUB' not found. The requested module
'../src/data/competitors.js' is a CommonJS module ...
error Command failed with exit code 1.
```
Build command that fails: `frontend/package.json` → `"build": "vite build && node scripts/seo-prerender.mjs"`.

## Root cause
`frontend/scripts/seo-prerender.mjs` is executed **directly by Node** (not by Vite). It statically imports named exports from `frontend/src/data/competitors.js`.

- `frontend/package.json` has **no `"type": "module"`**, so Node classifies a `.js` file as **CommonJS**.
- When ESM imports a CJS file, Node uses `cjs-module-lexer` to statically guess the named exports. `competitors.js` is written with pure ESM syntax (`export const …`). The lexer surfaces the exports declared *before* the ~450-line `COMPETITORS` object (`LAST_VERIFIED`, `COMPETITORS`) but **fails to surface the ones declared after it** — `ALL_SLUGS` (line 493) and `COMPARE_HUB` (line 495). Hence the link-time error names `COMPARE_HUB`.
- Vite/vitest are unaffected because they treat all source as ESM regardless of `package.json` type — that's why the React pages (`CompareHub.jsx`, `VsPage.jsx`) and the unit tests build/pass. Only the raw `node scripts/seo-prerender.mjs` invocation hits Node's CJS interop path.

This shipped with bundle item (2) "build-time static prerender snapshots (dist/vs/*, dist/compare)" + the new single-source `competitors.js`.

## Fix (recommended — minimal blast radius)
Make Node load the data file as a true ES module by giving it an `.mjs` extension:

1. **Rename** `frontend/src/data/competitors.js` → `frontend/src/data/competitors.mjs` (content unchanged — it's already pure `export const` ESM).
2. **Update** `frontend/scripts/seo-prerender.mjs` line 25:
   ```js
   import { COMPETITORS, COMPARE_HUB, LAST_VERIFIED } from "../src/data/competitors.mjs";
   ```
   (Optional cosmetic: line 19 docstring still says `competitors.js`.)

The React pages import the file **extensionless** (`from "../data/competitors"`), and `vite.config.js` does **not** override `resolve.extensions`, so Vite's default resolution (`.mjs` is first) picks up `competitors.mjs` transparently. Vitest shares the same resolver. No React/component/test edits are required.

### Why NOT `"type": "module"`
Setting `"type":"module"` on `frontend/package.json` would force every `.js` in the frontend to ESM and **break the build**: `postcss.config.js` and `tailwind.config.js` use `module.exports` (CJS), and `vite.config.js` uses `__dirname` (a CJS-only global). Rejected.

### Why NOT Node's suggested `import pkg from …; const {…} = pkg;`
That default-import form only works if the file is genuinely CJS. `competitors.js` uses ESM `export const`, so loading it as CJS would throw `Unexpected token 'export'` at execution. The extension change is the correct fix.
